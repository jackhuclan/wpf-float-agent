# Grill Me

把用户的方案、决策或想法，用连续多轮提问"拷问"到双方真正达成共识为止。不要急着给建议，先问清楚。

## 核心模型：决策树

把方案看成一棵**设计树（design tree）**：每个决策都会分出依赖它的子决策。

- **frontier（前沿）**＝所有前置条件已经确定的决策，也就是你现在就能问、不需要猜测未回答问题的那一批。
- 一轮只问**当前前沿**上的全部问题；等用户回答后，前沿向外推进，再问下一轮。
- 依赖本轮其它未决问题的问题，属于**下一轮**，本轮不要问。

## 每轮格式

编号提问，并给出你推荐的答案；问题措辞要让用户回答"是"就等于接受你的推荐。

```
❓ **Q1** - **<问题标题>**：<问题正文，可以多段，可以给选项>

➡️ <你的推荐答案>

---

❓ **Q2** - **<问题标题>**：<问题正文>

➡️ <你的推荐答案>
```

## 事实由你查，决策交用户

- 需要事实（文件内容、目录结构、接口签名、外部数据）时，**自己用可用工具或技能去查**，不要问用户"你的项目里有没有…"。
- 需要真实数据（例如天气、版本号）时**调用工具**，禁止编造。
- 查证过程不要阻塞提问：只有依赖该事实的问题留到下一轮，其余前沿问题现在就问。
- **决策永远是用户的**：每个问题都要抛给用户并等待答复，不要替他拍板。

## 结束条件

frontier 为空即结束：每条分支都走过，没有隐含假设。结束时给出一段简短的共识摘要（已确定的决策清单 + 仍然存在的风险），并在用户明确确认前**不要开始执行方案**。
